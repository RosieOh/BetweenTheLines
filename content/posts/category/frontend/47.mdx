# 상수를 전부 분리하는 게 맞을까

서버 렌더링 템플릿 안에 인라인 `<script>`가 잔뜩 들어간 프로젝트를 맡았습니다.
Django 템플릿 20여 개에 각각 수십~수백 줄씩 있는 구조입니다.

정리하고 싶어서 이렇게 물었습니다.

> "templates 디렉토리 페이지들 내 자바스크립트에서 상수화는 전부 분리하는 게 맞을까?"

결론부터 쓰면 **아니었습니다.** 그리고 그 이유가 이 글의 절반입니다.

## 🚫 애초에 분리가 불가능한 것들

템플릿 안의 "상수"를 열어보니 대부분 이런 것이었습니다.

```js
const ALL_ITEMS = {{ items_json|safe }};                 // DB에서 온 데이터
const API_URL   = '{% url "app:stats_data" %}';          // URL 역참조
const CSRF      = '{{ csrf_token }}';                    // 요청마다 다름
const selYear   = {{ sel_year }};                        // 뷰 컨텍스트
```

**전부 Django가 서버에서 렌더링해 넣는 값입니다.**

`static/js/*.js`는 Django가 렌더링하지 않고 그대로 서빙합니다.
이걸 통째로 옮기면 `{{ items_json }}`이라는 문자열이 브라우저에 그대로 박힙니다.

즉 이 부류는 **물리적으로 분리가 안 됩니다.** 이름이 대문자 `const`라고 상수인 게 아닙니다.

## 📏 기준 1 — "상수냐"가 아니라 "서버 결합이냐"

판단 축을 바꾸니 정리가 됐습니다.

| 종류 | 예시 | 분리? |
| --- | --- | --- |
| **서버 렌더링 값** | `ALL_ITEMS`, `API_URL`, `CSRF`, `selYear`, `IS_ADMIN` | ❌ 인라인 유지 |
| **페이지별 순수 상수** | `MAX_CHARS`, 색상 배열, 등급 라벨 매핑 | △ 여러 페이지가 공유할 때만 |
| **진짜 전역 순수 함수** | `getCookie`, `escapeHtml`, 숫자 포맷터 | ✅ 분리 |

"상수를 분리한다"는 목표를 세우면 첫 줄부터 막힙니다.
**"서버에 묶인 것과 아닌 것을 가른다"** 로 바꾸면 진행이 됩니다.

## 🔍 기준 2 — 이름이 아니라 본문을 대조하라

중복을 찾으려고 스캐너를 짰습니다. 함수를 추출해 **정규화된 본문**으로 비교하는 방식입니다.

```python
# 주석 제거 + 모든 공백을 단일 스페이스로
# 그리고 함수명 자체도 'function ('로 치환 → 이름만 다른 동일 함수도 잡힘
```

두 개의 인덱스를 만들었습니다.

- `by_body` — 본문이 100% 같은 것 (진짜 중복)
- `by_name` — **이름은 같은데 본문이 다른 것** (함정)

결과가 흥미로웠습니다.

```
[A] 본문 100% 동일 :  6건
[B] 이름 같고 본문 다름 : 25건
```

**함정이 진짜 중복의 4배였습니다.**

이름만 보고 "이거 중복이네" 하고 합쳤으면 사고가 났을 것들입니다.

| 함수 | 겉보기 | 실제 |
| --- | --- | --- |
| `showAlert` (3곳) | 중복 | ❌ CSS 클래스·아이콘·타임아웃(3s/4s)이 전부 다름 |
| `exportExcel` (2곳) | 중복 | ❌ 필터 수집이 element id 기반 vs FormData 기반. **겹치는 건 마지막 한 줄뿐** |
| `escapeHtml` (3곳) | 중복 | ⚠️ 한 곳은 **4문자만** 이스케이프 (작은따옴표 누락) |
| `renderTop5` (4곳) | 중복 | ⚠️ 데이터 키가 서로 다름 → 합치려면 설계가 필요 |
| 날짜 유틸 9개 | 중복 | ✅ 줄바꿈·주석만 다르고 로직 동일 |

`exportExcel`이 특히 교훈적이었습니다. **공통 부분이 `location.href = URL + '?' + qs` 한 줄**이었습니다.
이걸 함수로 뽑는 건 과잉 추상화입니다.

그리고 스캐너가 **놓친 것**도 있었습니다.
IIFE로 감싼 통짜 코드 블록은 `function NAME(` 패턴에 안 걸립니다.
두 페이지에 완전히 같은 블록이 있었는데 도구로는 안 나왔습니다.

> **도구는 후보를 주고, 판단은 본문 대조로 해야 합니다.**

## 🧲 기준 3 — 결합이 숨어 있으면 남긴다

본문이 같아도 안 합친 것들이 있습니다.

**전역 가변 상태에 묶인 것**

```js
function trendOpts() {
  return { ...  trendPeriods ... };   // 페이지 전역 가변 변수
}
```

공용 파일로 옮기면 **크로스파일 가변 전역**이 생깁니다.
9줄 아끼려고 추적하기 어려운 의존성을 만드는 건 손해입니다.

**모듈 세계가 다른 것**

한쪽은 레이아웃을 상속하는 앱 페이지고, 다른 쪽은 독립 인쇄용 페이지였습니다.
9줄짜리 함수 하나 때문에 두 세계를 잇는 건 맞지 않습니다.

**타이밍에 묶인 것** — 이게 제일 미묘했습니다.

지도 iframe 오버레이를 제어하는 코드가 있었습니다.
이걸 공용 JS로 빼서 페이지 하단에 로드했더니, `iframe.onload` 핸들러가 **늦게 붙었습니다.**
iframe이 먼저 로드되면 오버레이가 영영 안 사라집니다. "로딩 중..." 이 고정됩니다.

결국 JS로 빼지 않고 **`{% include %}` 부분 템플릿**으로 원위치에 유지했습니다.

**의도적 중복**

에러 페이지(403/404/500)의 CSS가 중복이었는데, 주석에 이렇게 적혀 있었습니다.

```
외부 CSS/JS 의존성 0
```

**static이 죽어도 에러 페이지는 떠야 합니다.** 이건 공통화하면 안 되는 중복입니다.

## 🧟 죽은 코드 찾기 — 그리고 오탐

별도 감사 스크립트로 호출되지 않는 함수를 찾았습니다. 4건이 나왔습니다.

그중 하나는 **오탐**이었습니다.

```js
.then(render)     // ← 괄호 없이 참조로 전달
```

`render()` 형태로 호출되지 않으니 "죽었다"고 판정된 것입니다.
콜백으로 넘기는 패턴을 스캐너가 못 봤습니다.

나머지 3건은 진짜였고, 하나를 지우니 **연쇄 고아**가 드러났습니다.
그 함수만 쓰던 헬퍼가 같이 죽은 코드가 된 것입니다. 함께 제거했습니다.

```
최종: 4개 함수, 29줄 삭제, 삽입 0
```

## 🎨 CSS는 왜 안 건드렸나

같은 감사에서 CSS도 쟀습니다.

```
인라인 <style> 총 1,249줄 (20개 템플릿)
2곳 이상 100% 동일한 규칙 134건
```

숫자만 보면 정리 대상입니다. 그런데 **안 했습니다.**

- 실익이 약 100줄인데 JS 정리는 465줄이었습니다 (우선순위)
- **시각 회귀는 문법 체크로 안 잡힙니다.** 눈으로 전 페이지를 봐야 합니다
- 스캐너가 `@media` 블록 안의 규칙을 최상위로 잘못 집계하는 한계가 있었습니다

마지막이 중요합니다. **내 측정 도구의 한계를 알면 그 수치를 근거로 큰 변경을 하면 안 됩니다.**

## 💥 예상 못 한 복병 — 에디터 포매터

커밋 직전에 이상한 걸 발견했습니다.

**10줄을 지웠는데 diff가 361줄**이었습니다.

원인은 에디터의 format-on-save였습니다.
공백이 의미를 갖는 코드 예시 블록을 포매터가 재포맷해버린 것입니다.

```
AUTH_MODE = 'prod'      # 'dev' → 'prod' (설명)
```
가 이렇게 쪼개졌습니다.
```
AUTH_MODE = 'prod'
# 'dev' → 'prod' (설명)
```

**렌더링 결과는 안 바뀔 가능성이 컸습니다.** 해당 CSS에 `white-space: pre`가 없어서
브라우저가 어차피 공백을 접기 때문입니다.

그래도 되돌렸습니다. 이유는 단순합니다.

> **내 작업과 무관한 포매터 노이즈를 커밋에 섞을 이유가 없습니다.**

리뷰어가 361줄 중 10줄을 찾아야 하고, 나중에 blame이 오염되고,
"이 변경이 렌더링에 영향을 주나?"를 매번 다시 판단해야 합니다.

되돌린 뒤 포매터가 다시 개입하지 못하도록 **바이트 단위로 그 10줄만 재적용**했습니다.
(줄바꿈 문자까지 보존해야 했습니다.)

### 오염을 감지하는 방법

이후로는 커밋 전에 이걸 확인합니다.

```bash
git diff --numstat <file>
git diff --numstat --ignore-all-space --ignore-blank-lines <file>
```

**두 수치가 다르면 포매터가 개입한 것입니다.**

최종 커밋에서는 10개 파일 전부 두 값이 일치했습니다.

며칠 뒤 같은 종류가 또 나왔습니다. 이번엔 다른 플러그인이 파일 맨 위에
자동 생성 헤더 주석을 박아뒀습니다. 동작에는 무해하지만 다음 커밋에 딸려 들어갑니다.
**제가 수정할 파일이 아니었으므로 아예 손대지 않고 커밋에서 배제**했습니다.

## 🧪 검증 — 함수의 "존재"가 아니라 "실행"

리팩터링 후 검증이 까다로웠습니다. 전역 함수를 옮겼으니 로드 순서가 어긋나면 조용히 깨집니다.

헤드리스 브라우저로 7개 페이지를 돌면서 두 가지를 봤습니다.

**① 전역 스코프에 있는가**

```js
typeof window['getDateRange']   // 'function' or 'undefined'
```

**② 실제로 실행됐는가**

```js
document.querySelector('#periodText').textContent
// "검색 기간 : 2025년 ~ 2026년"
```

②가 핵심입니다. **이 텍스트가 렌더됐다는 건 공용으로 옮긴 날짜 함수들이 실제로 돌았다는 증거**입니다.
`typeof`만 확인하면 "정의는 됐는데 안 불린" 경우를 못 잡습니다.

결과도 의도대로였습니다.

```
stats 페이지  : 11개 전역 전부 function
그 외 페이지  : 공용 5개만 function, stats 전용 6개는 undefined  ← 격리 확인
```

**어디에 있어야 하는가만큼 어디에 없어야 하는가도 확인**했습니다.

그리고 가장 위험했던 검사 하나.

> 새로 만든 전역 `function` 이름이 기존 `const`/`let`과 충돌하는지 스캔 → **0건**

충돌하면 `SyntaxError`로 **스크립트 전체가 죽습니다.** 페이지가 통째로 하얘집니다.

부분 템플릿을 도입할 때는 **렌더된 HTML을 바이트 단위로 비교**했습니다.
변경 전후 출력이 완전히 동일함을 확인했습니다. 스크린샷보다 강한 검증입니다.

## 🧱 2라운드 — JS를 뺐더니 DOM이 남았다

공용 모듈 3개로 정리하고 나서 깨달은 게 있습니다.

> **JS는 공용 모듈로 뺐는데, 그 모듈이 의존하는 DOM은 여전히 복붙 상태였습니다.**

`getDateRange()`가 `#dfYear` 같은 id를 읽는데, 그 마크업은 페이지마다 복사돼 있었습니다.
한쪽에서 id 하나만 바꿔도 공용 함수가 **조용히** 깨지는 구조입니다.

`{% include %}` 부분 템플릿 3개로 마크업도 묶었습니다.

| 부분 템플릿 | 고정한 계약 |
| --- | --- |
| 날짜 필터 | `getDateRange()` `initFilters()` `resetFilters()` |
| 지도 영역 | `sendMapData()` + 오버레이 제어 |
| 확인 모달 | `openConfirm()` `closeConfirm()` |

**함수와 그 함수가 읽는 DOM은 같이 움직여야 합니다.**
JS만 공통화하면 계약이 반쪽만 보장됩니다.

참고로 이 프로젝트는 그전까지 `{% include %}` 사용이 **0건**이었습니다.

## 📌 정리

- **"상수를 분리한다"는 목표는 서버 렌더링 템플릿에서 첫 줄부터 막힙니다.** 기준을 "서버 결합 여부"로 바꾸세요
- 중복 스캐너는 **후보만** 줍니다. 이름이 같은 25개 중 합칠 수 있는 건 소수였습니다
- **본문을 정규화해서 대조**하세요. 함수명까지 치환하면 이름만 다른 동일 함수도 잡힙니다
- IIFE 같은 건 **함수 스캔에 안 걸립니다.** 도구의 사각지대를 알고 쓰세요
- 본문이 같아도 **전역 가변 상태·모듈 세계·로드 타이밍**에 묶여 있으면 남기세요
- **의도적 중복**이 있습니다. 에러 페이지의 "외부 의존성 0"처럼요
- 측정 도구에 한계가 있으면 **그 수치로 큰 변경을 하지 마세요**
- `git diff --numstat`을 **공백 무시 옵션과 비교**하면 포매터 오염이 보입니다
- 검증은 **함수의 존재가 아니라 실행 결과**로 하세요. 그리고 **없어야 할 곳에 없는지도** 확인하세요
- 새 전역 이름이 기존 `const`/`let`과 충돌하면 **스크립트 전체가 죽습니다.** 반드시 스캔하세요
- **JS만 공통화하면 DOM 계약이 반쪽입니다.** 함수와 마크업은 같이 움직여야 합니다
