# [Friday] 297개 라벨을 40개로

[지난 글](/post/40)에서 Claude Code 세션 로그를 파싱해 SQLite 그래프로 만들었습니다.
프로젝트·세션·모델·파일이 노드로 들어갔는데, 그래프가 영 시시했습니다.

세션은 프로젝트에만 붙어 있고, **서로 다른 프로젝트의 비슷한 작업이 연결되지 않았습니다.**
"Jenkins 파이프라인"을 세 프로젝트에서 했는데 그래프에선 남남이었습니다.

주제(topic) 노드가 필요했습니다. 그리고 이건 결정적 파싱으로는 안 되니, 파이프라인에서 **유일하게 LLM을 쓰는 단계**가 됐습니다.

## 🔌 API 키 없이 LLM 부르기

먼저 사소하지만 유용한 이야기. API 키를 발급받지 않았습니다.

```python
CLAUDE = shutil.which("claude.cmd") or shutil.which("claude")
MODEL = "claude-opus-5"

# print mode 로 호출 — 이미 로그인된 Claude Code 인증을 그대로 사용
[CLAUDE, "-p", "--model", MODEL, "--output-format", "json"]
```

로컬 `claude` CLI를 print 모드로 부르면 **이 머신에 이미 있는 로그인을 재사용**합니다.
개인 도구라면 이게 제일 간단합니다. 나중에 서버로 옮길 거면 `call_claude()` 하나만 SDK로 바꾸면 되도록 감싸뒀습니다.

## 💀 사건 — `claude -p`가 조용히 실패했다

호출을 붙이자마자 막혔습니다. **stdout이 비어서 오는데 종료 코드는 0이고 stderr도 없었습니다.**

처음엔 프롬프트가 6천 자쯤 되니 Windows 명령줄 길이 제한을 의심했습니다. 틀렸습니다.
argv 길이는 문제가 아니었습니다.

진짜 원인은 이거였습니다.

> Windows에서 `claude`는 `.cmd` 배치 래퍼로 해석됩니다.
> **cmd.exe는 인자를 첫 줄바꿈에서 잘라버립니다.**
> 여러 줄 프롬프트가 조용히 잘린 채 전달되고, 종료 코드는 0, stderr는 없습니다.

멀티라인 프롬프트를 인자로 넘기면 첫 줄만 전달되는 것이었습니다.
그러니 모델은 맥락 없는 한 줄을 받고 빈 응답을 돌려준 셈입니다.

해결은 **stdin**입니다.

```python
# 프롬프트를 stdin 으로 보내면 cmd.exe 의 파싱을 통째로 우회합니다
subprocess.run([CLAUDE, "-p", ...], input=prompt, ...)
```

코드에 주석으로 남겼습니다. 다시 만나면 또 헤맬 종류의 함정이라서요.

## 🏷️ 1단계 — 세션마다 주제 뽑기

각 세션에서 **사용자 발화만** 뽑아 모델에 넘겼습니다.

```python
# 최대 14개 메시지, 메시지당 280자, 전체 5500자
# "Tool results and system reminders are noise for this
#  — what the person actually typed is the signal."
```

도구 결과를 넣지 않은 게 핵심입니다. 바이트의 대부분은 도구 출력인데,
**"이 세션이 무엇에 관한 것인가"를 결정하는 건 사람이 친 문장**입니다.

프롬프트에는 제약을 박아넣었습니다.

- 주제 2~5개
- "프로젝트명·사람이름·파일명은 주제가 아닙니다"
- "너무 일반적인 것(개발, 코딩, 작업)은 제외"
- JSON만 출력

72개 세션을 돌렸습니다. 결과는 이랬습니다.

```
297개 라벨,  그중 88% 가 단 1개 세션에만 등장
```

## 🤔 진단 — 동의어가 아니었다

당연히 "동의어를 합치자"고 생각했습니다. 전체 목록을 주고 병합을 시켰습니다.

```
297 → 266
```

31개밖에 안 줄었습니다. 여기서 멈춰서 라벨을 직접 읽어봤습니다.

```
커밋 메시지 규칙
커밋 메시지 정리
커밋 및 푸시
구조화된 커밋 작성
커밋 컨벤션 적용
```

**이것들은 동의어가 아닙니다.** 문장으로 보면 실제로 다른 말입니다.
"커밋 메시지 규칙"과 "커밋 및 푸시"는 다른 작업이죠.

모델은 주제를 뽑은 게 아니라 **작업 설명을 요약**하고 있었습니다.
그리고 작업 설명은 세션마다 다를 수밖에 없습니다. 88%가 1회성인 게 당연했습니다.

문제는 동의어가 아니라 **입도(granularity)** 였습니다.

## 🔄 해결 — 순서를 뒤집다

병합을 잘하려고 애쓰는 대신, **목표 어휘를 먼저 고정**했습니다.

```
기존:  세션 → 라벨 297개 → 병합 시도 → 266개  ❌
변경:  세션 → 라벨 297개 → 택소노미 40개 도출 → 라벨을 거기에 배정 → 40개  ✅
```

2단계에서 상위 카테고리 25~40개를 설계하게 했습니다.
프롬프트에 **실패 사례를 그대로 박아넣은 게** 효과가 컸습니다.

```
같은 주제가 다른 표현으로 흩어져 있습니다.
(예: "커밋 메시지 규칙", "커밋 메시지 정리", "커밋 및 푸시"가 전부 따로)

'개발', '기타' 처럼 아무거나 들어가는 카테고리는 금지입니다.
```

3단계에서 297개 라벨을 그 40개에 배정합니다. 여기도 제약이 중요했습니다.

```
이 목록 밖의 값은 절대 쓰지 마세요.
입력 라벨 전부가 결과에 정확히 한 번씩 나와야 합니다.
새 카테고리를 만들지 마세요.
```

결과는 **297 → 40**. 상위 주제가 각각 6~12개 세션을 묶었습니다.

```
Git·버전관리 12   커밋 컨벤션·이력 관리 12   프로젝트 구조·환경 설정 12
관리자·대시보드 기능 11   기술 문서화 11   시스템 아키텍처 설계 11
```

이제 그래프가 연결됩니다. `커밋 컨벤션`은 **11개 프로젝트**에 걸쳐 있고,
`배포 자동화`는 6개 프로젝트에 걸쳐 있다는 게 한눈에 보입니다.

원본 라벨은 버리지 않고 `session_topic.raw`에 보존해서, 주제 노트에 `Merged from:`으로 노출했습니다.
"이 40개는 어디서 왔나"를 추적할 수 있어야 하니까요.

## 💀 사건 2 — 파서가 라벨 60개를 날렸다

택소노미를 적용했는데 297 → 99에서 멈췄습니다. 60개 라벨이 원본 그대로 남아 있었습니다.

응답 JSON을 파싱하는 코드가 이랬습니다.

```python
# 첫 '{' 부터 마지막 '}' 까지 잘라서 파싱
```

긴 매핑 응답은 **객체 여러 개로 쪼개져서** 옵니다.

```json
{"a": "X", "b": "Y"}
{"c": "Z", "d": "W"}
```

이걸 첫 `{`~마지막 `}`로 자르면 `Extra data` 에러가 나고, 그 청크가 통째로 버려집니다.
청크 하나가 라벨 60개를 물고 있었습니다.

`raw_decode`로 순차 파싱하고 병합하도록 고쳤습니다.

```python
decoder = json.JSONDecoder()
# 여러 객체를 순서대로 디코드해서 합친다
```

파서 수정 후 **297 → 40**이 나왔습니다.

폴백도 2단으로 뒀습니다. 택소노미 밖의 값이 오거나 라벨이 누락되면 **원본 라벨을 유지**합니다.
조용히 버리는 것보다 낫습니다.

## 💾 캐시 — 재실행마다 라벨이 바뀌면 안 된다

LLM 분류의 가장 큰 문제는 **비결정성**입니다.
같은 데이터로 다시 돌렸는데 라벨이 바뀌면 노트 이름이 바뀌고 링크가 다 깨집니다.

3층으로 캐싱했습니다.

| 캐시 | 내용 |
| --- | --- |
| `topic_run` | 세션별 1단계 결과 |
| `taxonomy` | 카테고리 어휘 |
| `topic_map` | 라벨 → 카테고리 배정 |

그리고 **언제 어휘를 다시 뽑을지**를 규칙으로 정했습니다.

```python
stale = cats and len(fresh) > max(20, 0.25 * len(labels))
```

새 라벨 중 기존 택소노미에 매핑되지 않는 게 **전체의 25%를 넘거나 20개를 초과**하면
어휘 자체가 낡았다고 보고 2단계를 다시 돌립니다. 그 외에는 캐시를 씁니다.

어휘가 바뀌면 배정 캐시는 통째로 버립니다.

```python
con.execute("DELETE FROM topic_map")  # categories changed
```

효과는 명확했습니다.

```
1회차 (캐시 없음) → LLM 호출 7회
2회차 (캐시 있음) → LLM 호출 0회
```

캐시 전에는 아무것도 안 바뀌었어도 매번 7회를 냈습니다.

## 📌 정리

- Windows에서 `claude`는 `.cmd` 래퍼입니다. **멀티라인 프롬프트는 인자가 아니라 stdin으로** 넘기세요. 안 그러면 조용히 잘립니다
- 분류 입력에서 **도구 출력은 노이즈**입니다. 사람이 친 문장이 신호입니다
- 라벨이 파편화될 때 **"동의어를 합쳐라"는 거의 안 듣습니다.** 동의어가 아니라 입도 문제인 경우가 많습니다
- **목표 어휘를 먼저 고정하고 배정하는 순서**가 실제로 효과가 있습니다
- 프롬프트에 **실패 사례를 그대로 넣으면** 모델이 무엇을 피해야 하는지 훨씬 잘 압니다
- LLM 응답 JSON은 **객체 여러 개로 쪼개져 옵니다.** 첫 `{`~마지막 `}` 슬라이싱은 언젠가 터집니다
- 분류 결과를 캐싱하지 않으면 **재실행마다 라벨이 흔들려** 하위 산출물이 전부 깨집니다
