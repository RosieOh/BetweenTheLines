# [Friday] 재생성 도구가 내 데이터를 지웠다

[Friday](/post/40)는 Claude Code 세션 로그를 Obsidian 볼트로 렌더합니다.
`obsidian.py`를 돌리면 Sessions·Projects·Models·Topics·Transcripts 폴더가 통째로 다시 만들어집니다.

**재생성 가능한 도구**라는 게 설계의 전제였습니다. 언제든 지우고 다시 만들면 되니까요.
그 전제가 틀린 곳이 하나 있었습니다.

## 🕰️ 프루닝은 왜 필요했나

처음엔 정리 로직이 없었습니다. 그냥 덮어쓰기만 했습니다.

문제는 [주제 분류](/post/41)에서 나왔습니다. 택소노미를 다시 도출하면 **주제 이름이 바뀝니다.**
`컨테이너 운영` 이 `컨테이너·Docker` 로 바뀌면 옛 이름의 노트가 그대로 남습니다.

어느 날 폴더를 보니 이랬습니다.

```
Topics: 82개    (실제 주제는 40개)
```

절반이 유령이었습니다. 그래서 `prune_stale()`을 만들었습니다.
기준은 단순하게 잡았습니다. **"이번 실행에 생성되지 않은 노트는 지운다."**

42개를 정리했고, 재실행해도 개수가 안 늘어났습니다. 잘 됐다고 생각했습니다.

## 💀 사고

한참 뒤, 다른 작업을 마치고 `obsidian.py`를 다시 돌렸습니다.
출력을 보는데 숫자가 하나 줄어 있었습니다.

```
Transcripts: 73 → 72
```

세션이 사라진 것도 아닌데 대화 노트가 하나 없어졌습니다.

원인을 추적했습니다. 대화 노트가 없는 세션이 4개 있었고, 이유가 갈렸습니다.

- **3개** — 원본 `jsonl`이 이미 사라짐. Claude Code가 오래된 transcript를 주기적으로 정리합니다
- **1개** — `user` 레코드가 전부 IDE 주입이고 assistant 응답이 없는, 열자마자 중단된 세션 (정상)

그리고 73 → 72의 정체는 이거였습니다.

> **원본이 사라진 세션의 대화 노트를, 내 `prune_stale`이 지웠습니다.**
> 원본이 없으니 그 노트가 유일한 기록이었는데 삭제했습니다.

복구는 불가능했습니다.

- `vault/`는 대화 내용이 들어가므로 **gitignore 대상**입니다. git에 없습니다
- `Path.unlink()`는 **휴지통을 거치지 않습니다**

대화 하나가 그냥 없어졌습니다.

## 🔍 무엇이 잘못됐나

`prune_stale`의 기준이 **"이번 실행에 생성되지 않았다"** 였습니다.
그런데 이 조건은 서로 다른 두 상황을 하나로 묶습니다.

| 상황 | 노트가 재생성되지 않은 이유 | 올바른 처리 |
| --- | --- | --- |
| 주제 이름이 바뀜 | 그 카테고리가 더는 존재하지 않음 | **삭제해야 함** |
| 원본 jsonl이 로테이션됨 | 다시 읽을 소스가 없음 | **절대 삭제하면 안 됨** |

둘 다 "이번에 안 만들어짐"으로 똑같이 보입니다.
**"만들 필요가 없어진 것"과 "만들 수 없었던 것"을 구분하지 못한 것**이 사고의 본질입니다.

재생성 도구를 짤 때 흔히 하는 가정이 있습니다.

> 소스가 진실이고, 출력은 언제든 다시 만들 수 있다.

이건 **소스가 계속 존재할 때만** 참입니다.
Claude Code는 오래된 transcript를 지웁니다. 그 순간 출력이 유일한 사본이 됩니다.
**파생물이 원본이 되는 지점**이 있었고, 저는 그걸 못 봤습니다.

## 🛠️ 고친 방법

### 규칙 1 — 내가 만든 것만 지운다

먼저 소유권 검사를 넣었습니다. 이 생성기가 붙인 `type:` frontmatter가 있는 파일만 삭제합니다.

```python
head = p.read_text(encoding="utf-8")[:200]
if ("type: %s" % type_name) not in head:
    continue                      # not ours -- leave it
p.unlink()
```

손으로 쓴 노트가 같은 폴더에 있어도 안전합니다.
실제로 볼트 루트에 직접 작성한 노트가 몇 개 있는데, 그것들은 이 검사로 살아남습니다.

### 규칙 2 — Transcripts는 기준이 다르다

핵심은 이겁니다. **폴더마다 프루닝 기준을 달리했습니다.**

```python
# Transcripts are keyed to sessions that still exist, NOT to what was
# regenerated this run. Claude Code eventually removes old transcripts from
# ~/.claude, and when that happens the note is the only surviving copy of
# the conversation -- pruning on "wasn't rebuilt this time" destroys it.
keep_transcripts = {n + " (대화)" for n in used_names}
```

- **Sessions·Projects·Models·Topics** — "이번 실행에 쓴 것"을 남깁니다 (전부 DB에서 다시 만들 수 있음)
- **Transcripts** — "현재 DB에 존재하는 세션"을 남깁니다

즉 대화 노트는 **세션 자체가 DB에서 사라졌을 때만** 지웁니다.
원본을 못 읽었다는 이유로는 절대 지우지 않습니다.

### 규칙 3 — 상태를 노트에 적는다

조용히 비어 있는 것보다 왜 비었는지 적히는 게 낫습니다. 3분기로 나눴습니다.

| 상황 | 노트 내용 |
| --- | --- |
| 대화를 읽음 | `전문: [[...|대화 기록 전문]] (N개 메시지)` |
| 원본 소실 + 기존 노트 있음 | `> [!info] 원본 transcript는 이미 삭제되었습니다. 이 노트가 유일한 기록입니다.` |
| 둘 다 없음 | `> [!warning] 기록된 대화가 없습니다 — 원본이 삭제되었거나 응답 없이 종료된 세션입니다.` |

두 번째 콜아웃이 중요합니다. **이 노트는 백업이 없다**는 걸 볼 때마다 알려줍니다.

## 📉 그런데 대화 노트는 왜 넣었나

사실 처음에는 대화 본문을 볼트에 **안 넣었습니다.** 시크릿 유출이 걱정돼서였습니다.

그러다 노트를 보니 이런 상태였습니다.

```
| turns | 1722 |
| output tokens | 304,573 |
| cache read | 24,426,824 (92% hit) |
```

**"1722턴, 캐시 92%"만 있고 무엇을 결정했는지가 없었습니다.**
세컨드브레인으로선 반쪽이었습니다.

넣기로 한 근거는 감이 아니라 측정이었습니다. 용량부터 쟀습니다.

```
원문 jsonl 합계 : 340 MB
사용자 발화     :   0.6 MB
Claude 텍스트   :   2.8 MB
────────────────────────
읽을 수 있는 대화 :  3.4 MB   (1.0%)
```

**도구 호출과 도구 결과가 바이트의 99%, 의미의 거의 0%** 였습니다.
그걸 버리면 340MB가 3.4MB가 되고, 볼트가 충분히 감당합니다.

그래서 대화만 별도 노트로 분리했습니다. 별도로 둔 이유도 있습니다.
최대 단일 세션이 **527KB**라 세션 노트에 인라인하면 열리지 않고,
그래프 뷰에서 70여 개 잎 노드가 매달려 노이즈만 됩니다. `-path:Transcripts`로 걸러냅니다.

같은 이유로 **파일 노드 4,225개는 wikilink가 아니라 frontmatter**로 넣었습니다.
링크로 만들면 그래프가 읽을 수 없는 털뭉치가 됩니다.

## 📌 정리

- **"재생성 가능하다"는 가정은 소스가 계속 존재할 때만 참입니다.** 소스가 로테이션되는 순간 파생물이 원본이 됩니다
- 프루닝 기준으로 **"이번에 안 만들어짐"은 위험합니다.** *만들 필요가 없어진 것*과 *만들 수 없었던 것*을 구분하지 못합니다
- **폴더마다 프루닝 기준이 달라도 됩니다.** 전부 같은 규칙을 적용하려는 욕심이 사고를 만들었습니다
- 생성기가 만든 파일에는 **소유권 표식**을 남기세요. 남의 파일을 지우지 않게 됩니다
- `unlink()`는 휴지통을 안 거칩니다. **gitignore 된 디렉터리에서 파일을 지우는 코드**는 특히 조심해야 합니다
- 데이터를 넣을지 말지는 **먼저 재보고** 결정하세요. "너무 클 것 같다"는 직감이 1%를 340MB로 착각하게 만들었습니다
- 비어 있는 것과 **왜 비었는지 적힌 것**은 다릅니다. 조용한 실패를 남기지 마세요
